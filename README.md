# 教學小遊戲：翻牌配對、大小排序、連連看

教學用的小遊戲合集。老師自訂題庫與圖片，學生用滑鼠或平板觸控來玩。三個遊戲共用同一份題庫。
純前端網頁，不需要伺服器、帳號或網路；題庫與圖片只存在使用者自己的瀏覽器裡。

線上版：https://patalim.github.io/order-line/

## 開始使用

**最簡單的方式：單機版。** 執行 `node scripts/build-standalone.js` 會在 `dist/` 產生單一檔案 `教學小遊戲.html`，把它複製給別人，雙擊用瀏覽器開就能玩，不需要伺服器或網路（詳見下方「單機版」）。

另外兩種方式：

原始碼由多個檔案組成，**不能直接雙擊 `index.html` 開啟**（瀏覽器在 `file://` 下會擋掉模組載入），需要用下列任一方式：

- **本機**：在這個資料夾開啟終端機，執行 `python -m http.server 8123`，再用瀏覽器開 `http://localhost:8123`。
- **放到網路上**：把整個資料夾放到 GitHub Pages 或任何靜態網站空間即可。

## 三個遊戲

畫面上方的選單可以切換：翻牌配對、大小排序、連連看、題庫管理。遊戲進行中（或題庫編輯到一半）切換時會先確認，避免不小心離開。

### 翻牌配對

1. 在設定畫面選**題庫**、**牌數**（4×4、6×6，或自選組數）與**玩家人數**。
2. 多人時可以輸入每個人的名字；「配對成功可再翻一次」預設開啟，可以取消。
3. 點牌翻開，每翻兩張算一步。配對成功的牌會留在桌上，失敗的會蓋回去。
4. 多人輪流時，畫面會標示輪到誰與各人配對數；結束時顯示排名，同分並列。
5. 單人局會記錄「題庫＋牌數」的最少步數與最短時間，破紀錄時結果視窗會提示。

**牌背**：可選蓋起來時顯示「？」或「編號」（1、2、3…，依牌的位置）。編號比較不會讓年紀小的學生有失敗感，老師也能直接喊「請翻 5 號」。

**記憶時間**：可選 3、5、10 秒。開局時所有牌先全部亮出並倒數，時間到（或按「開始！」）才蓋牌，計時從第一次翻牌才開始。記憶模式的最佳紀錄與一般模式分開計算。

### 大小排序

從題庫抽出幾張卡片（2～12 張），學生**拖曳卡片**排好大小，按「揭曉答案」。

- 排序時看不到數值，揭曉後才顯示；答對的卡片標綠色、答錯的標紅色，答錯時下方會顯示正確順序。
- 可選「由小到大」或「由大到小」。
- 數值相同（並列）的卡片，順序任意都算對。
- 滑鼠與觸控都能拖曳；也可以把焦點放在卡片上，用方向鍵移動。
- 計時、累計得分（答對的張數）。

### 連連看

左邊是卡片、右邊是打亂的數值（2～10 組）。**先點左邊再點右邊**，兩邊就會連起來；點已連好的項目可以拆線重連。

- 「顯示正確答案」：答對的線標綠色實線、答錯的標紅色，並用綠色虛線補上正確答案。
- 「核對答案（不顯示答案）」：答對的線變綠色並**鎖定**，答錯的線變紅色但不顯示答案。下一位玩家一開始操作，紅線就會自動清除，接著連剩下的，讓全班可以接力。
- 數值相同（並列）時，連到任一個都算對。
- 累計得分與大小排序共用，重新整理頁面後歸零。

## 做自己的題庫

按上方選單的「題庫管理」。

- **新增題庫**：每一組配對有兩張牌，各自可以選「文字」或「圖片」，所以圖配圖、圖配字、字配字都可以，同一個題庫也能混用。
- **數值（選填）**：每組可以填「數值」與「單位」（例如 `10.4`、`g`）。**大小排序與連連看只會用到有數值的組**；題庫至少要有 2 組有數值才能玩。
- **第二張牌「自動」**：有數值時，第二張牌可以選「自動」，翻牌配對時牌面直接用「數值＋單位」。所以「水果 ↔ 含糖量」只要填名稱與數值，三個遊戲都能玩。
- **圖片**：支援 PNG、JPG、GIF、WebP；不接受 SVG。上傳後會自動縮到最長邊約 600 像素再儲存（GIF 動畫只保留第一格）。第一張牌是圖片時，可以再填一行「說明文字」顯示在圖片下方。
- **內建題庫**不能修改；想改的話按「複製」，再編輯副本。內建有「動物（圖配字）」「算式配答案」「水果含糖量（每100克）」。
- 玩 4×4 的翻牌配對至少要有 8 組、6×6 至少 18 組；題庫的組數比這局需要的多時，每局會隨機抽選。

**多個題目共用同一個答案**（翻牌配對）：各建一組配對，答案填一樣的就行。例如「3+4 ↔ 7」和「5+2 ↔ 7」，桌上會有兩張「7」；「3+4」翻到任何一張「7」都算配對成功。文字會忽略頭尾空白；圖片要是同一張圖才算一樣。

### 匯入與匯出

- **匯出**：每個題庫有「匯出」（`.json`，含圖片）；「匯出全部題庫」把自己的所有題庫存成一個檔案。
- **匯入**：同一個「匯入」按鈕可以讀：
  - 本遊戲匯出的 JSON（單一題庫或整個題庫庫）；
  - 舊版 order-line 匯出的 JSON；
  - **CSV**：欄位為「名稱、數值、單位」，匯入成一個題庫（以檔名命名）；加上第一欄「主題」（`主題,名稱,數值,單位`）則依主題一次建立多個題庫。可按「下載 CSV 範本」取得範例；
  - **Excel**（`.xlsx`／`.xls`）：欄位同 CSV。讀取 Excel 需要網路（用到時才下載讀取元件）；沒有網路時請先另存成 CSV。
- 匯入前會完整檢查，檔案有任何問題就整個拒絕，不會匯入一半。匯入的題庫一律是新增，不會覆蓋既有題庫。

## 資料存在哪裡

| 內容 | 位置 |
| :--- | :--- |
| 題庫與圖片 | 瀏覽器的 IndexedDB |
| 設定、最佳紀錄 | 瀏覽器的 localStorage |
| 累計得分 | 只在目前這次開啟期間，重新整理後歸零 |

- 資料只在**同一個瀏覽器、同一個網址**下看得到；換電腦或換瀏覽器不會跟過去，請用匯出／匯入搬移。
- 清除瀏覽器的網站資料會一併清掉題庫與紀錄，重要的題庫請先匯出備份。
- 無痕模式或封鎖網站資料時，無法儲存題庫，只能玩內建題庫；遊戲本身仍可使用。
- **從舊版 order-line 升級**：第一次開啟時，會自動把舊版存在瀏覽器裡的主題轉成題庫（有圖片的卡片轉成「圖片＋說明文字」）。舊資料不會被刪除；沒改過的內建水果範例不會重複出現。

## 單機版

```
node scripts/build-standalone.js
```

會產生 `dist/教學小遊戲.html`：CSS、所有程式、網頁圖示都內嵌在同一個檔案裡，雙擊即可用瀏覽器開啟，也可以放隨身碟或寄給別人。腳本只用 Node 內建模組，不需要安裝任何套件。

- 改過程式後要重新執行一次才會更新；`dist/` 不放進版本控制。
- 以 `file://` 開啟時，題庫與紀錄存在瀏覽器裡「這個檔案」的名下：**換一個資料夾或換檔名，可能會看不到原本的題庫**。搬移題庫請用匯出／匯入。
- 部分瀏覽器（例如 Safari、Firefox 的某些設定）在 `file://` 下不允許儲存資料，此時只能玩內建題庫，遊戲本身仍可使用。建議用 Chrome 或 Edge。
- 想要真正的桌面程式（.exe／.app）需要另外用 Electron 或 Tauri 包裝，這會引入第三方工具，目前沒有做。這個單一 HTML 檔就是要包進去的內容，不需要改程式。

## 平板與觸控

按鈕與牌都做得很大，滑鼠與觸控都能操作，直放橫放與手機寬度都會自動調整版面。橫放的矮螢幕上，翻牌配對的步數、計時與玩家資訊會移到左側，讓牌桌盡量大。支援深色模式（跟隨系統設定）。

## 開發

- 原生 HTML／CSS／JavaScript（ES module），無建置工具、無第三方套件（Excel 讀取元件除外，且只在匯入 Excel 時才從網路載入）。
- 測試：`node --test`
- 單機版：`node scripts/build-standalone.js`（合併時會檢查不支援的 import 寫法與頂層名稱衝突，所以不同檔案的頂層名稱不能重複）
- 目錄：
  - `src/game/`：純函式的遊戲規則（翻牌、洗牌、排序、連連看、計分、排名、紀錄），不碰 DOM 與儲存。
  - `src/store/`：題庫模型與驗證、匯出入、CSV、舊版資料轉換與遷移、圖片格式判斷、設定與紀錄的儲存。
  - `src/ui/`：畫面、牌桌、拖曳排序、音效（Web Audio 合成，沒有音檔）。
  - `src/data/`：內建範例題庫。
  - `scripts/`：單機版打包腳本。
  - `docs/需求.md`：需求與決策。

## 已知限制

- 內建範例題庫的「圖」是 emoji 文字，真正的圖片請自己上傳。
- 水果含糖量是約略值（參考 USDA 食品資料庫），上課前建議自行核對。
- 沒有桌面程式（.exe／.app）；單機版是單一 HTML 檔。
